# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Evee is a home-inventory app concept — an interactive isometric apartment with navigation, a built-in floor-plan editor, chat sidebar, panels, and overlays. The **front-end** has no build step: React 18 + Babel Standalone are loaded from unpkg CDN and JSX is transformed in-browser via `<script type="text/babel" data-presets="react">`.

A thin **Python backend** ([serve.py](serve.py)) serves the static files *and* proxies inventory + chat + voice to Notion, the Anthropic API, and ElevenLabs (so secrets never reach the browser, and Notion's CORS block is sidestepped) — see **Notion inventory backend** under Architecture. There is no bundler, no test suite, no lint config. The only runtime dependency is `anthropic` (for the AI chat), in [requirements.txt](requirements.txt) — the voice ([tts_service.py](tts_service.py)) is stdlib-only. Secrets live in `.env` (gitignored); copy [.env.example](.env.example). To set up the voice, see **Running**.


## Source structure

`Evee.html` is a thin shell — just the HTML skeleton, CSS, CDN script tags, and 9 `<script type="text/babel" src="hifi/xxx.jsx">` tags. **The `hifi/*.jsx` files are the source of truth.** Edit them directly; no sync step needed.

Load order (everything shares one global scope, no modules):
`iso.jsx` → `world.jsx` → `scenes.jsx` → `chat.jsx` → `panels.jsx` → `editor.jsx` → `room-editor.jsx` → `api.jsx` → `app.jsx`
(`api.jsx` = backend fetch helpers; loads before `app.jsx`, which calls them.)

Backend (Python, stdlib + `anthropic`): `serve.py` (dev server + `/api/*` routes), `inventory_service.py` (Notion REST mapping), `chat_service.py` (AI tool loop), `tts_service.py` (ElevenLabs voice out), `stt_service.py` (ElevenLabs Scribe, voice in), `backup.py` (snapshot the DB).

## Running

Requires the local server (browsers block XHR to `file://` paths, which Babel Standalone uses to load the `.jsx` files; the server also provides the `/api/*` backend).

```sh
./start.sh          # runs serve.py, opens http://localhost:8000/Evee.html
# or manually:
python3 serve.py 8000
```

Then visit `http://localhost:8000/Evee.html`. `serve.py` loads `.env` at startup (restart after editing it). **It binds `127.0.0.1` only** — `/api/*` has no auth of its own and proxies the Notion database plus the Anthropic/ElevenLabs keys, so it must not be reachable from the LAN. Remote access is meant to go through Tailscale (below), which proxies from loopback and is unaffected. `EVEE_BIND=0.0.0.0` (env or `.env`) reopens every interface if you really want plain-HTTP LAN access — the startup banner prints whichever address it bound to. The app **degrades gracefully** when the backend/Notion/Anthropic isn't configured — inventory falls back to legacy counts and the chat replies that it's not configured. To enable everything: set `NOTION_TOKEN` + `NOTION_DATABASE_ID` (and `ANTHROPIC_API_KEY` + `pip install -r requirements.txt` for chat) in `.env`. See [README.md](README.md) for the one-time Notion setup.

**Voice setup (ElevenLabs).** Evee's spoken voice is optional — without it she stays silent (the chat still works as text). To enable it, add to `.env`:

```sh
ELEVENLABS_API_KEY=sk_...        # ElevenLabs dashboard → API Keys (copy on create — shown once)
ELEVENLABS_VOICE_ID=...          # open a voice in the app → "Copy Voice ID"
# ELEVENLABS_MODEL=eleven_flash_v2_5   # optional; default. Flash = lowest latency
```

No extra packages needed ([tts_service.py](tts_service.py) is stdlib-only — `urllib`). **Restart `serve.py`** after editing `.env`; the startup log prints `ElevenLabs voice: configured` (or not). The key never reaches the browser — audio is synthesized server-side and streamed back (`POST /api/tts` → `GET /api/tts/{id}`). See **Notion inventory backend** under Architecture for the request flow, and the Chat-UI bullet for the client-side `useSpeech`.

**Installing to an iPad home screen (PWA).** [manifest.webmanifest](manifest.webmanifest) + `apple-mobile-web-app-capable` in [Evee.html](Evee.html) make "Add to Home Screen" launch **standalone**, without the Safari toolbar. This only works over real HTTPS, so it depends on the Tailscale URL — it could not have worked over the plain-HTTP LAN address. `icons/evee-*.png` (Evee's orb, generated by a stdlib-only script — there is no PIL on the server and no build step to add one) back the `apple-touch-icon`, the favicon, and the manifest; without an `apple-touch-icon` iOS uses a screenshot of the page as the tile. `serve.py` maps `.webmanifest` to `application/manifest+json` explicitly, since Python's default table omits it and the browser ignores a manifest served as `application/octet-stream`.

**Live reload.** `serve.py` streams Server-Sent Events at `GET /api/livereload`: a `{boot, v}` heartbeat where `boot` is a per-process id and `v` is the newest mtime across `Evee.html`, `hifi/*.jsx` and `*.py`. A small plain-`<script>` block in [Evee.html](Evee.html) subscribes and reloads when either value moves — so an edit, **or a server restart**, refreshes every connected device with no manual reload. Deliberate details: it is **not** a `type="text/babel"` script (a JSX syntax error would otherwise leave the page unable to reload itself), it ignores changes for the first 3s so it can never loop on startup, and it waits on `window.__eveeBusy` (set by App from `listening || eveeSpeaking`) so a reload never cuts Evee off mid-sentence. SSE rather than a websocket: plain HTTP/1.1, no dependency, and it rides through the Tailscale HTTPS proxy unchanged.

**Remote access over HTTPS (Tailscale).** The always-on server Mac publishes Evee at **`https://evee-server.<your-tailnet>.ts.net`** (real, auto-renewing Let's Encrypt cert) to devices signed into the tailnet. This exists for one reason: **the mic needs a secure context.** `getUserMedia` / Web Speech only run over HTTPS or localhost, so plain-HTTP LAN (`http://192.168.1.x:8000`) could only ever have given remote devices text chat and Evee's TTS — **no voice input**. Certs can't be issued for private IPs, so the `*.ts.net` **name** is what must be used — not `100.x`, not the LAN IP. That LAN fallback is now closed anyway: the server binds loopback (see Running), so the tailnet is the only way in from another device.

`tailscaled` runs **rootless, in userspace-networking mode**, via [launchd/com.evee.tailscaled.plist](launchd/com.evee.tailscaled.plist), because `sudo brew services start tailscale` needs a password and the box is administered remotely. Consequences:

- **Every `tailscale` command needs `--socket`** — the daemon is not at the default path:
  ```sh
  tailscale --socket=$HOME/.tailscale/tailscaled.sock status
  tailscale --socket=$HOME/.tailscale/tailscaled.sock serve status
  ```
- **The server Mac cannot resolve its own `.ts.net` name.** MagicDNS needs root to rewrite system DNS, so `curl https://evee-server…` from the box fails with a DNS error (curl exit 6). That is expected, **not** a broken proxy — other devices resolve fine via their own client. On the server itself use `http://localhost:8000` (localhost is a secure context, so the mic works there too).
- **Every other device needs the Tailscale client** installed and signed into the same tailnet, or the name does not resolve at all ("server can't be found").
- **`tailscale serve` hangs forever if HTTPS certs aren't enabled for the tailnet** — no error, it just blocks on `/localapi/v0/query-feature`. The tell is `CertDomains: null` in `tailscale status --json`; enable it at `login.tailscale.com/admin/dns`. The serve config itself lives in the statedir and survives daemon restarts.
- **The HTTPS origin is a *different origin* from the LAN URL**, so it gets its own `localStorage` — a device moving to it re-seeds the layout from `home.json` instead of carrying its old plan over (see Persistence).

## Architecture

- **Isometric projection** ([hifi/iso.jsx](hifi/iso.jsx)): world coords `x→right-back, y→front, z→up`, projected via `proj(x,y,z)`. `ISO.S` is the world-unit→pixel scale. `ISO.TILT` controls camera angle (0.5 = standard 2:1 iso, higher = more top-down). Use `isoPath()` to build SVG paths from world-space polygons, `boxFaces()` for box top/right/front faces, and `bbox()` / `centroid()` for polygon helpers.
- **World data** ([hifi/world.jsx](hifi/world.jsx)): `APARTMENT` (rooms), `HOME_FURNITURE` (per-room furniture), `STORAGE_AREAS` (per-room storage targets). Default layout seeded from **`home.json`** (the apartment this was built for) via `python3 tools/seed_world.py home.json`, which rewrites the three literals in place — author layout changes in the editor, ⋮ Save Plan over `home.json`, then re-run the script instead of hand-editing. It round-trips every key, including `shape` (`'circle'` furniture) and `groupId`. **Declared as `let` (not `const`)** so App can reassign them when state changes — see Gotchas below.
- **Rooms are polygons.** Each room is `{ id, name, color, items, points: [{x,y}, ...] }` — a closed polygon outline in world units (≈ 1 foot). Legacy rect form `{x, y, w, d}` is still supported as a fallback throughout the renderers (use `bbox(room.points)` to derive a bounding box). Optional room flags: `hideName` (skip label), `noInteract` (skip hit zone — used for wall infills), `groupId` (multiple rooms can share one logical id for hover/click — used for the hallway union), `wallOverrides` (per-edge wall map, see RoomScene below), `viewRot` (0–3, persisted room-view rotation, see RoomScene below), `homeOrder` (integer; the room's back→front render slot in the home view, see HomeScene below).
- **Scenes** ([hifi/scenes.jsx](hifi/scenes.jsx)): `HomeScene` (dollhouse iso view of the whole apartment) and `RoomScene` (single-room zoom). Furniture coords are room-local relative to the bbox origin. **`HomeScene` draws furniture one whole room at a time, rooms ordered back→front by `homeRoomOrder(rooms)`** (`room.homeOrder` if set, else the room's centroid depth `x+y`); within each room it sorts at the default angle via `isoDepthSort(furn, 0)`. This per-room grouping is deliberate: a single global furniture sort across rooms hits cross-room **occlusion cycles** at shared walls (two rooms' pieces interlock so no flat draw order is correct, and something pokes through). Grouping makes every piece in a nearer room draw over every piece in a farther one, and only pieces *within* a room compete geometrically. (`isoDepthSort` itself uses a Kahn topological sort of the pairwise separating-axis order; when a genuine cycle stalls it, it force-releases the shallowest leftover to break one edge and continues, rather than dumping the remainder by a scalar.) `RoomScene` renders the polygon floor + cutaway walls; an edge gets a wall when it is **back-facing AND not shared with another room**. Back-facing = edge midpoint has smaller `x+y` than the polygon centroid. Shared = a point nudged just outside the edge (along its normal) lands inside another room's polygon — tested with the `pointInPolygon` helper, so interior walls between adjacent rooms (e.g. living↔patio, living↔kitchen) are not drawn. A room's `wallOverrides` overrides this per edge **per view angle** — shape `{ [rot]: { [edgeIdx]: boolean } }` (`true` = force wall, `false` = force none, absent = use heuristic) — resolved via `wallOverrideFor(room, rot, i)`, which also honors a legacy flat `{ [edgeIdx]: boolean }` (all-angle) shape as a fallback. Because the back-facing heuristic is itself angle-dependent, keying overrides by `rot` lets each rotation show its own walls. **Non-storage furniture in `RoomScene` renders with `pointerEvents:'none'`** so hovers/clicks pass through to storage-area glow paths behind them. **Room-view rotation** (`rot` prop, 0–3 quarter-turns) is applied by rotating the room-local outline + furniture *upstream* of the render pipeline (`rotPoint` / `rotRect` helpers) so depth-sort, the back-face wall test, and projection all work unchanged on the rotated coords. `shared` is computed from the *unrotated* world geometry (camera-independent) while `isBack` uses the rotated outline; edge index stays aligned so `wallOverrides[i]` survives rotation. Furniture `w`/`d` swap on odd turns. `boxFaces` always draws top/right/front, so furniture shading rotates with the scene — acceptable for 90° snaps.
- **Floor-plan editor** ([hifi/editor.jsx](hifi/editor.jsx)): top-down 2D editor for the **whole apartment** (room shapes) — drag a room body to translate, drag vertices to reshape, click an edge midpoint to split, right-click a vertex to delete. Snaps to 1 inch (`1/12` ft). All helpers prefixed `ed*` (edSnap, edFmtFt, etc.) to avoid collisions.
- **Room editor** ([hifi/room-editor.jsx](hifi/room-editor.jsx)): top-down 2D editor for **one room's interior** — add/move/resize/delete furniture, edit label/color/dims/height/lift z, reorder layers, toggle a piece as a storage unit, and toggle per-edge walls **for the current view angle** (cycles auto → on → off via the edge-midpoint buttons, writing `room.wallOverrides[viewRot]`; legacy flat overrides are migrated to the per-angle shape on first edit, and the canvas's auto-wall indicator is computed at `viewRot` so it matches what shows from that angle). Reached via the "Modify Room" `⋮` menu item (room view only). Helpers prefixed `re*` (reSnap, reFmtFt, reEffZ). **Rotation is in 45° steps** — `R` / `⇧R` (or the ↺ ↻ buttons in the panel's Angle row) turn the whole selection as one rigid body: each piece spins on its own centre *and* orbits the selection's centre, so a group keeps its shape. Resize handles work in the piece's own frame (the pointer delta is un-rotated first), so dragging a corner of a diagonal piece grows it along its own axes. See the `angle` gotcha below. Toggling "storage unit" on a piece sets `storage:true` on the furniture and adds a matching `STORAGE_AREAS[roomId]` entry `{ id, label, furniture, face, items }` (face = front/top/front2); toggling off removes it. **Furniture draw order is stored per view angle.** A piece's explicit order lives in `zOrders[rot]` (rot = 0–3 quarter-turns); the effective key is `reEffZ(it, rot) = it.zOrders?.[rot] ?? it.zOrder ?? (it.z||0)+(it.h||0)` (legacy scalar `zOrder` is honored as a per-angle fallback). The **Order** section's buttons (⤓ Back / ↓ / ↑ / ⤒ Front) operate **on the room's current `viewRot` only**: they take the exact back→front order shown at that rotation (`isoDepthSort(items.map(it => rotRect(it, rot, W, D)), rot)` — same pipeline RoomScene uses), move the selected piece one slot (or to an end), then stamp **every** piece with a contiguous integer in its `zOrders[rot]` slot. Other angles keep their own order, so each of the four rotations can be arranged to look correct independently. `isoDepthSort(items, rot)` treats the per-angle explicit order as **authoritative** (see scenes.jsx) — so the iso render at a given angle matches what was arranged for it. Angles never touched (and rooms never reordered) keep the geometric depth sort. To set another angle, rotate the room (↺/↻ in room view) then re-open Modify Room; the editor authors whichever `viewRot` the room is currently at. A separate **Home view layer** section (below the live preview, collapsible and closed by default — its collapsed header shows the room's `n/total` render slot) shows a **draggable list** of the interactive rooms in render order (front→back, top row = front/on-top); dragging a room and dropping it on another reorders it, then stamps every interactive room with a contiguous integer `homeOrder` (so explicit ranks and the geometric-depth fallback never mix). This is the per-room analogue of furniture order and is what fixes furniture from one room poking through a neighbour at a shared wall.
- **Furniture catalog** ([hifi/room-editor.jsx](hifi/room-editor.jsx)): saved assemblies, reusable across rooms — the same flat-pack cabinet stands in three rooms here, and rebuilding it from twenty boxes each time is the thing this removes. `⤓ Save to catalog` in the room-editor panel turns the current selection into a `CATALOG` entry `{ id, name, w, d, h, created, pieces }`; the `CatalogRail` down the left of the room editor lists them (iso thumbnails drawn by the same `Box` renderer as the rooms, so a card looks like what it places) and one click drops that assembly into the room being edited, centred and selected as one fresh group. Entries live **in the plan** (`state/plan.json` → `catalog`), so the library syncs across devices with the layout; it is not in Notion (it's geometry, not inventory). Two deliberate details: (1) **piece ids are not stored** — an id is also a container id and the Notion join key, so a placed copy mints fresh ids and fresh, *empty* containers, and a storage piece travels with its container's label/face instead (`reCatalogEntry`/`rePlaceEntry`); (2) **draw order travels as dense 0-based ranks per view angle**, and only for angles the source room actually arranged — on placement they are offset above the target room's highest rank, so the assembly's internal order survives while where it sits against the room's other furniture stays geometric (`isoDepthSort` only compares ranks when both pieces carry one) until the Order buttons say otherwise. Deleting an entry never touches copies already placed — those are ordinary furniture in their rooms, and always were.
- **App state** ([hifi/app.jsx](hifi/app.jsx)): views are `HOME`, `ROOM`, `EDITOR`, `ROOM_EDIT`. App holds the apartment state (`apt`, `furniture`, `storageAreas`, `catalog`) lifted from the world.jsx defaults and seeded from localStorage. `RoomEditor` receives `apt`/`setApt` (for wall overrides) plus `furniture`/`storageAreas` setters. Keyboard: `Esc` unwinds the deepest layer, `⌘K` opens search, `⌘E` toggles chat. The `⋮` menu in TopBar offers Modify Room (room view only), Create Floor Plan, Load Floor Plan, Save Plan (the file-based plan format is `{version, width, depth, name, rooms, furniture, storageAreas, catalog}` — note it carries the home `name` and does **not** include inventory items, which live in Notion; a file from before the catalog existed leaves the saved furniture alone rather than wiping it). Load Floor Plan warns before replacing the layout if there are existing containers/items (the new ids unlink any Notion rows keyed to the old ones).
  - **TopBar title** is the editable home name, stored on `apt.name` (click to rename; empty falls back to the placeholder "Your Home Name Here"). It persists in `localStorage` with the plan and round-trips through Save/Load Plan. The subtitle shows `<items> items · <containers> containers`, where item counts come from live Notion via `itemCount(area)` (= `INVENTORY[area.id]?.length`, falling back to the legacy scalar `area.items`); containers = total area count.
  - **Room view** has ↺/↻ buttons (bottom-right) that call `rotateActiveRoom(±1)`, writing the room's `viewRot` so the orientation persists. `SceneStage` swaps the camera-bounds width/depth on odd quarter-turns.
- **Chat is Claude-backed** (Phase 2). `sendUserMessage` ([hifi/app.jsx](hifi/app.jsx)) sends the full conversation history plus a live rooms/containers directory to `POST /api/chat`, which runs an Anthropic Messages API tool-use loop ([chat_service.py](chat_service.py), default `claude-haiku-4-5`) whose tools (`list_items`/`add_item`/`update_item`/`remove_item`) wrap the same `inventory_service.py` functions the manual panel uses — so AI and manual edits hit the same Notion DB. A fifth tool, **`open_room`**, lets her drive the view ("open the kitchen", "show me the fridge", "take me back home"). `room_id` accepts the reserved value **`"home"`** for the whole-apartment view — the dollhouse is not a room and has no directory entry, so without it she has nothing to target and will say she can't go back. It touches no inventory: the server has no router, so it returns the target and `handle()` lifts it out of `changes` into a separate **`navigate`** field — keeping it out of `changes` matters, because a non-empty `changes` triggers a client inventory reload. App's `apiChat().then()` calls `goTo(roomId, containerId)` with it, the same navigator Search/Recent/Alerts use. The client reloads inventory when the response reports changes. `add_item` rejects a `container_id` not in the directory (so the AI can't write an orphaned row). Degrades gracefully (replies "not configured") when `ANTHROPIC_API_KEY` / the `anthropic` package are absent. Chat history is in-memory only (lost on reload).
  - **Chat UI** ([hifi/chat.jsx](hifi/chat.jsx)): a persistent `VoiceWidget` (a big blue/purple animated "AI blob", `EveeAvatar3`) is anchored **bottom-right** and never moves — tapping it toggles voice (`listening`); a wider "Ask Evee" tab tucked *behind* it opens the **text chat**, which slides in as a **left** `ChatSidebar` (text-only composer; voice input is the blob). When a right-docked panel opens (`panelOpen`/`selectedArea`), the widget slides left of it. A transparent scrim closes the chat on any outside click; the TopBar (zIndex 59) and the blob (62) sit above the scrim (58) so both stay interactive while chatting. **Voice I/O + shared `eveeMood` live in App** (not in chat). **Speech-to-text:** tapping the blob runs `useSpeechRecognition` ([hifi/chat.jsx](hifi/chat.jsx)) — despite the name it is **`MediaRecorder` + server-side transcription** (`apiTranscribe` → `POST /api/stt` → ElevenLabs Scribe, [stt_service.py](stt_service.py)), not the browser's Web Speech API. Tap once → record → **auto-stop after ~1.2s of silence** (an `AnalyserNode` watching RMS, since MediaRecorder has no pause-detection of its own) → transcribe → send; 20s cap; tap again to cancel; a voice result opens the chat. **`getUserMedia` is not instant** (a few hundred ms on iOS, longer right after Evee spoke — the audio session has to leave playback), and nothing can shorten it: pre-warming a stream is precisely what wedges iOS in `playAndRecord`. So the hook exposes a third state, **`arming`** — the tap landed, the mic is not live yet — which drives the `waking` orb mood and a bubble drawn at random from **`MIC_WAKE_LINES`** (102 short lines of AI-flavoured nonsense — "Contexting the tokens…", "Judging your fridge…" — with the honest "Waking the mic…" left in the pool, and no line repeating twice running — the picker, `micWakeLine()`, is module-level so that rule spans every caller). Turning dead air into a small surprise is the whole point, so keep them short and don't collapse the pool back to one string. It is deliberately not folded into `listening`: the ripples are the cue to start talking, and there is no recorder yet, so anything said would be lost. **`armingRef` also guards re-entry** — during the await neither `streamRef` nor `recRef` exists, so before this a second tap opened a *second* capture and the first stream was overwritten without ever being released, which is the exact way to wedge the mic. There is **no live interim transcript** (recording yields nothing until the API returns), so `interim` only ever carries filler: when recording stops it takes a *second* `MIC_WAKE_LINES` pick, and **that line has to cover the rest of the turn**. App latches it (`waitLine`) and holds the bubble up (`waiting`) long after the hook goes idle — through transcription, `/api/chat`, and the `/api/tts` fetch — until `speak()`'s **`onStart`** fires on the first frame of actual sound. Every earlier cutoff is wrong: the transcript landing opens the chat but answers nothing, and `speech.speaking` flips true a whole fetch before any sound, so both leave the user watching a silent blob through the last and longest seconds of the wait. `waiting` therefore also outranks `eveeSpeaking` in `eveeMood` (the orb keeps thinking until she really talks); a mic tap, muting, or a reply that produced no audio ends it too. STT pins the language via `ELEVENLABS_STT_LANG` (default `eng`) — left to auto-detect, Scribe will occasionally transcribe a short or quiet clip as confident gibberish in another language. **Releasing the mic is load-bearing, not hygiene:** `releaseMic()` stops every track *before* the transcription round-trip, because Web Speech's un-releasable stream is exactly what used to wedge iOS in `playAndRecord` — see the iOS gotcha below. **Text-to-speech:** `useSpeech` speaks each reply with Evee's **ElevenLabs** voice. `apiSpeakUrl` POSTs the text to `/api/tts`, gets back a one-shot URL, and points the reusable `<audio>` at it, so playback starts on the **first mp3 bytes** rather than after the whole file (~0.15s off a typical reply; more as replies get longer). The two steps exist because `<audio>` can stream a URL but cannot POST, and her replies name the user's own things — those don't belong in a query string. There is **no browser-voice fallback** — if ElevenLabs is unconfigured/errors she stays quiet. The reply **caption reveal** is driven by her voice (proportional to audio playback time, applied monotonically so it never jumps back), with a timed typewriter used only to animate the caption when muted or no audio was produced. **While the mp3 is still streaming, `audio.duration` is `Infinity`**, so the reveal falls back to an estimate from the text (13 chars/sec — deliberately the slow end, since progress is applied monotonically and running behind self-corrects while running ahead would not) until a real duration exists. (`useSpeech`'s `stopAudio` detaches the `<audio>` handlers before clearing `src` — setting `src=''` fires a spurious `error` event that otherwise re-triggers playback/fallback.) `voiceOn` (🔊/🔇 in the chat header, persisted in `localStorage` key `evee-voice-on`) mutes her; tapping the blob to talk and muting both barge in (stop her mid-sentence). The greeting is never spoken on load — only replies received during the session. `reveal`/`mood`/`status` are passed down so the chat avatar and blob share one mood (idle/listening/thinking/speaking) and the reveal survives the chat closing/reopening. `EveeAvatar3` is pure CSS/SVG (breathing, blink, ripples, glow, a rotating "liquid" swirl).
- **Floor plan backend** ([plan_service.py](plan_service.py)) — stdlib-only store for the layout under `state/plan.json`, seeded from `home.json`. `GET /api/plan` → `{rev, updated, plan}`; `PUT /api/plan` `{rev, plan}` → `{rev}` or **409** with the server's copy attached. Writes are atomic (temp file + `os.replace` — a torn write costs a floor plan that took hours) and snapshot into `state/backups/` with the same rotation shape as [backup.py](backup.py). A `threading.RLock` guards writes, since `serve.py` is threaded. See **Persistence**.
- **Notion inventory backend** — inventory **items** live in **Notion** (one row per item); the floor-plan **layout** is server-side too now (above), no longer `localStorage`. [serve.py](serve.py) (threaded, loads `.env`) exposes `GET/POST/PATCH/DELETE /api/inventory`, `POST /api/inventory/relabel`, `POST /api/chat`, and Evee's voice as a pair — `POST /api/tts` registers the text in a short-lived (5 min) in-memory `TTS_JOBS` map and returns `{url}`, then `GET /api/tts/{id}` opens [tts_service.py](tts_service.py)'s stdlib-only wrapper over ElevenLabs' `/stream` endpoint and forwards chunks as they arrive. The response carries no `Content-Length` — it ends when the connection closes, which works because `protocol_version` is HTTP/1.0 so every response closes anyway (the same reason the livereload SSE stream terminates). Finished bytes are cached on the job, so Safari re-requesting a media URL replays from memory instead of being billed twice. Config is checked at the **POST**, where the client can still catch it — inside an `<audio>` element the only signal is an opaque `error` event; unset `ELEVENLABS_API_KEY`/`ELEVENLABS_VOICE_ID` means Evee stays silent and the caption just shows, no browser voice). [inventory_service.py](inventory_service.py) is the stdlib-only Notion REST mapping (`list/create/update/delete/relabel_item`; resolves the data-source id for Notion API `2025-09-03`; retries on HTTP 429 honoring `Retry-After`). **Join keys:** a Notion row's `Container ID` = the storage area's `id`, `Room ID` = the room `id`. **Critically, `setStorage` seeds `area.id` from the furniture piece's `id`, so `area.id === furniture.id === Notion "Container ID"`** — see the orphaning gotcha. Client: [hifi/api.jsx](hifi/api.jsx) fetch helpers (`apiListInventory/Add/Update/Delete/RelabelContainer/Chat/SpeakUrl`, published to `window`). App holds an `inventory` state map keyed by container id, populated by `loadInventory()` on mount and after AI changes, and mirrored to the `INVENTORY` global + `itemCount(area)` helper ([hifi/world.jsx](hifi/world.jsx)) so scenes and the TopBar show live counts. **Inventory writes are optimistic + DEBOUNCED/coalesced per item** (a burst of qty-stepper clicks collapses into one PATCH carrying the final value, staying under Notion's ~3 req/s); the per-item debounce timers live in `pendingWrites` (a ref in App). An item delete = Notion **archive** (recoverable from Trash for 30 days). The `ItemSidePanel` ([hifi/panels.jsx](hifi/panels.jsx)) is the manual editor (add via the search box, rename inline, qty steppers, delete). **Backups:** [backup.py](backup.py) dumps all rows to a timestamped `backups/*.json` (keeps the last 30); scheduled daily via [launchd/com.evee.inventory-backup.plist](launchd/com.evee.inventory-backup.plist) (install instructions in the plist header).
- **TopBar overlays** ([hifi/panels.jsx](hifi/panels.jsx)) are fed live data derived in App + a shared `goTo(roomId, containerId)` navigator: `SearchOverlay` (⌘K) filters the loaded inventory (`allItems`) client-side by name/container/room; `TimelineOverlay` (⏱ Recent) lists items newest-first by Notion `created_time` (exposed as `item.created` by `inventory_service`); `AlertsOverlay` (⚠) shows a **Low stock** section (`quantity ≤ 1`) plus the orphaned-items section. The ⚠ badge shows iff `alertCount` (low-stock + orphans) is non-zero.

## Persistence

Two stores, by design:
- **Floor-plan layout** (rooms, furniture, container definitions, saved-furniture catalog, home name, theme) lives on the **server** in `state/plan.json` (gitignored), via [plan_service.py](plan_service.py) and `GET/PUT /api/plan`. Not in Notion — Notion is bad at geometry — but no longer per-browser either.
- **Inventory items** live in **Notion** (source of truth), loaded via the backend on mount.

**It used to be `localStorage`, and that was the bug.** `localStorage` is scoped per *origin*, so `http://localhost:8000` and the `https://…ts.net` URL kept separate copies and the iPad and Mac silently drifted to different furniture. `localStorage` under `evee-plan-v2` is now only a **cache**: it paints the first frame instantly and keeps the app renderable when the server is unreachable. The server's copy always wins on load.

**Sync model.** Writes are debounced ~600ms and coalesced (a furniture drag is one request, not one per frame) and carry the `rev` they were based on; a stale rev is refused with **409** carrying the server's current state, which the client adopts. Other clients are pushed to: the livereload SSE payload gained a `rev` alongside `{boot, v}`, and App subscribes with **its own** `EventSource` — reacting only to `rev`, ignoring `boot`/`v` — so the plain-`<script>` reloader in `Evee.html` stays untouched and a JSX error still can't cost the page its ability to reload.

⚠️ **`state/` must never join `WATCH_GLOBS`** ([serve.py](serve.py)). That list drives full page reloads; a plan write would reload every connected device on every edit, including the one making it. The rev rides *alongside* `v`, deliberately not as part of it.

**Offline is read-only.** If the initial `GET /api/plan` fails, the app renders from cache, shows an "offline · view only" chip in the TopBar, and disables every mutation entry point (Modify Room, Create/Load Floor Plan, Customize, room rotation). Save Plan stays enabled — it only reads. Editing into an unreconcilable local cache is exactly the divergence this replaced.

`evee-voice-on` stays per-device on purpose: a muted wall iPad and a talking laptop.

`home.json` + [tools/seed_world.py](tools/seed_world.py) are now **bootstrap only** — they seed `state/plan.json` the first time it is missing. To reset the layout during dev, `rm -rf state/` and reload. To promote the live layout back into the repo default, copy `state/plan.json`'s `plan` into `home.json`'s file-plan shape and re-run the seeder.

## Gotchas

- **Cross-file values are shared via `window`.** Each `hifi/*.jsx` is transformed and run as a *separate* Babel script, so top-level declarations are **not** automatically visible across files. Every file ends with `Object.assign(window, { … })` to publish its exports; components then reference them by bare identifier (e.g. `proj`, `APARTMENT`), which resolves to the global. Intra-file helpers (e.g. `rotPoint`/`rotRect` used only inside scenes.jsx) don't need publishing. When adding a top-level function/component that's used by another file, add it to that file's `Object.assign(window, …)`.
- **`APARTMENT` / `HOME_FURNITURE` / `STORAGE_AREAS` / `INVENTORY` are live globals that App rewrites each render.** They're declared `let` in [hifi/world.jsx](hifi/world.jsx) and seeded onto `window`; App reassigns both the binding and `window.*` each render (`APARTMENT = apt; window.APARTMENT = apt;`) so scenes that read the bare identifier see live edits. `INVENTORY` mirrors App's `inventory` state (keyed by container id) the same way — handlers in `room-editor.jsx` read it via the bare global to count items before a destructive action. If a scene ever shows stale data after a save, this mirroring is the thing to check.
- **Container identity = furniture id, and container ops *orphan* (never delete) Notion items.** Because `area.id === furniture.id === Notion "Container ID"`, anything that changes/destroys that id (toggling storage off, deleting the furniture piece, Load Floor Plan, clearing `localStorage`) **unlinks** the Notion rows — the rows are *not* deleted (only an explicit item delete archives a row, recoverable from Trash). Toggling storage back on for the *same* piece re-links them (id unchanged); deleting the piece orphans permanently (the id is gone). `setStorage(off)` and `deleteSelected` therefore `window.confirm` when `INVENTORY[id]` is non-empty. `addItem`/`duplicateSelected` add a random suffix to furniture ids so two pieces can't collide on an id. **Orphaned items** (inventory whose container id matches no storage area) surface in the **Alerts drawer** (⚠, `AlertsOverlay` in [hifi/panels.jsx](hifi/panels.jsx)) — keyed by the labels Notion still carries — with **re-link** (`reassign_container` + `POST /api/inventory/reassign`) to any existing container, or delete; the ⚠ badge shows only when the orphan count is non-zero.
- **The backend must be running for inventory/chat**, but the app never hard-fails without it: fetches are caught and the UI falls back to legacy counts / a "not configured" chat reply. `.env` holds the secrets (`NOTION_TOKEN`, `NOTION_DATABASE_ID`, `ANTHROPIC_API_KEY`) and is gitignored.
- **Any non-`noInteract` room is clickable** in `HomeScene` (the old `items > 0` click gate was removed so empty/new rooms can be opened and edited). Walls use `noInteract` to opt out of the hit zone. `items` now only feeds the displayed counts (defaults to `0` where absent).
- **Furniture may be a rect or a circle.** `shape: 'circle'` renders as a cylinder (`isCircle` branches in [hifi/scenes.jsx](hifi/scenes.jsx) and [hifi/room-editor.jsx](hifi/room-editor.jsx)); absent/`'rect'` is the box path. The seeded default has 14 circular pieces, so anything that copies or regenerates furniture must preserve `shape`.
- **Furniture may also be turned off-axis — `angle`, in degrees clockwise about its own footprint centre.** Not every room is square (the storage nook and the hallway run at 45°), so their furniture can't be either. `x/y/w/d` still describe the *unrotated* footprint and rotation is about its centre, which is rotation-invariant — so the anchor stays put and every centre-based helper (`AreaLabel`, shadows) is untouched. The editor rotates in **45° steps** and **bakes any result landing on a multiple of 90° back into `w`/`d`, dropping `angle`** (a w×d rect turned 90° *is* a d×w rect), so `angle` only ever marks a genuinely diagonal piece and every axis-aligned path stays on its original code path. Angled pieces render through `prismFaces` ([hifi/iso.jsx](hifi/iso.jsx)) — the top cap plus whichever vertical faces point at the camera (`nx + ny > 0`), each shaded from the azimuth of its own normal; at angle 0 it reproduces `boxFaces` exactly. A box turned exactly 45° shows **one** vertical face, its neighbours being edge-on — that is correct, not a missing face. `footprintBounds()` gives the axis-aligned bounds of a rotated footprint, and is what the depth sort, marquee hit test and selection box use; `isoDepthSort`'s separating-axis test only speaks rectangles, so a diagonal piece sorts by bounds that overstretch into its corners — the Order buttons are the fix when that reads wrong.
- **Furniture coords are room-local relative to bbox origin.** `HomeScene` translates by `bbox(r.points)` before rendering; `RoomScene` renders at the local coords directly. When repositioning furniture after editing a room's polygon, remember the bbox origin may have moved.
- **Editor modes render an entirely different DOM tree** — `FloorPlanEditor` (`EDITOR` view) and `RoomEditor` (`ROOM_EDIT` view) both return early from `App`, bypassing `SceneStage` / `TopBar`. The `⋮` menu, voice blob / chat, etc. are not present in either editor.
- **The room editor needs `apt`/`setApt`** (not just `furniture`/`storageAreas`) because wall overrides live on the room object inside `apt`. If you only pass furniture setters, wall toggles silently no-op.
- **Every hook in `RoomEditor` runs before its `!room` bail-out, and must stay that way.** The room being edited can vanish between renders now that the plan syncs — another device deleting it, or a plan loaded elsewhere — and an early return that skipped the keyboard `useEffect` took the *whole app* down with React's "rendered fewer hooks than expected": a blank page, not a missing panel. `items`/`area` are computed above the bail for the same reason (that effect's dep array reads `items`).
- **The listen backlog is load-bearing — `EveeServer.request_queue_size = 128`, never the stdlib default of 5.** One page load opens **~11 sockets at once** (HTML, manifest, the nine `text/babel` scripts Babel fetches by XHR, and the livereload stream), and each one must be its own connection because responses are HTTP/1.0 and so are never reused. With a backlog of 5 the rest overflow the accept queue and macOS **RSTs** them instead of queueing: Babel ends up silently short a file or three, and a missing `app.jsx` (or `chat.jsx`, whose globals App needs) renders as a **blank page with no console error**. It cost **69 of 132 loads — 52%** in `logs/server.log`, which is why it presented as "broken every other time"; the missing file was different every time, which is what made it look like a CDN or caching problem. After the fix: 0 failures in 440 requests at 44 simultaneous sockets, and a page load's wall time dropped 0.12s → 0.02s. 128 is the ceiling macOS honours (`kern.ipc.somaxconn`). Diagnose a recurrence by counting `/hifi/*.jsx` requests per `/Evee.html` in the log — a good load has all nine.
- **`handle_error` swallows `BrokenPipeError`/`ConnectionResetError`.** A page navigating away mid-request is routine; before this, those tracebacks were ~90% of `logs/server.log` and buried anything real. Don't restore the default handler.
- **Never capture the mic without releasing every track.** iOS switches the audio session to `playAndRecord` the moment anything captures audio, which routes playback down the call path — quiet, echo-cancelled, "phone speaker" sounding — and it only reverts when the capture is fully torn down. This is why the browser's Web Speech API is not usable here: it never exposes its `MediaStream`, so its capture cannot be released, and after one mic use *every* later reply plays back quiet and the mic itself goes unreliable. Confirmed by experiment: `getUserMedia` + `MediaRecorder` + `track.stop()` leaves playback at full volume, while Web Speech does not. Anything added later that touches `getUserMedia` must stop its tracks the same way.
- **iOS Safari needs two accommodations desktop doesn't** — both fixed; don't reintroduce them. (1) **Audio must be unlocked by a real gesture.** Evee speaks *after* an `await` on `/api/tts`, so an `Audio()` created at that point is outside the gesture context and iOS rejects `play()` with `NotAllowedError` (silently, if the caller swallows it). `useSpeech` therefore keeps **one** reusable `<audio>` and `unlock()`s it with a silent WAV from actual taps — the mic tap, opening the chat, and `sendUserMessage`. Do not go back to `new Audio()` per utterance, and do not let `stopAudio` null the element: that un-blesses it. (2) **Rounded clipping leaks.** Safari promotes a child with a transform animation or `mix-blend-mode` to its own compositing layer and then clips it to the **square** border box, ignoring the parent's `border-radius` — which let the orb's swirl escape as a visible square on iPad while Chromium looked fine. The fix is the no-op `WebkitMaskImage` on the core orb in `EveeAvatar3` ([hifi/chat.jsx](hifi/chat.jsx)); applying any mask forces Safari to composite against the rounded shape.
